# Fixed-seed RNG confound in Jericho LLM-agent evaluations — reproduction artifacts

[![tests](https://github.com/abahgat/jericho-seed-confound/actions/workflows/tests.yml/badge.svg)](https://github.com/abahgat/jericho-seed-confound/actions/workflows/tests.yml)

Reproduction package for the methods note of the same name. The note's two
demonstrations are generated by the scripts here and committed as machine-readable
JSON in [`data/`](data/), and the test suite re-derives their tabled numbers from
those files, so those claims and their evidence do not drift apart unnoticed. Two
things sit outside that loop: the prevalence screen is committed but will not
reproduce on a re-run, because GitHub code search is not deterministic (it is
re-verifiable row by row instead), and the note's hand-verified audit of the named
systems is a code read with no artifact here. See below.

## The finding in one paragraph

An unseeded `jericho.FrotzEnv(ROM)` — the ordinary construction — does not leave
the game unseeded. It silently binds the game's *walkthrough* seed: a fixed,
globally-constant value stored in each supported game's bindings for walkthrough
validation. Every unseeded run of a benchmark-suite game therefore replays one
frozen RNG tape, so stochastic in-game outcomes (combat survival, thief
encounters) become deterministic functions of the action path, and repeated runs
presented as independent samples are copies of a single draw. A falsy-coalescing
default (`seed or bindings.get('seed', -1)`) means an explicit `seed=0`
reintroduces the same bug.

## Verify the claims without running anything

The artifacts are committed, and the tests are stdlib + pytest — no game engine,
no ROM, no API keys, no network:

```bash
pip install -r requirements-test.txt
pytest -q
```

That re-derives, from `data/`:

- the unseeded default collapses 12 "independent" runs to **one** world state (SD 0.00);
- an explicit `seed=0` resolves to the **same** walkthrough seed (the falsy-coalescing trap);
- randomized positive seeds restore variation (11 of 12 distinct states);
- RNG-quiet padding leaves a downstream fight byte-identical while **one**
  RNG-consuming action flips it;
- the artifacts for jericho 3.2.0 and 3.3.1 agree in every field except the
  version string — the note's version-invariance claim, checked rather than asserted;
- and the sentences the demos print about all of the above, computed from the run
  rather than hardcoded — so a post-fix engine reports the confound as **absent**
  instead of repeating a conclusion its own numbers contradict.

## Regenerate the artifacts from scratch

This needs the engine and a Zork I game file (see below):

```bash
pip install -r requirements.txt
python seed_confound_demo.py --rom /path/to/zork1.z5 --out
python seed_path_demo.py     --rom /path/to/zork1.z5 --out
pytest -q          # the same tests now check your freshly generated files
```

Both demos are model-free and cost nothing to run: they replay a fixed prefix of
Jericho's own Zork I walkthrough, so agent behaviour is identical by construction
and the only thing varying is the engine seed (or, in the second demo, the path).

`--out` writes to `data/…_jericho-<version>.json`, so the filename follows
whichever engine is installed and regenerating never overwrites another version's
artifact. Reproducing the **version-invariance** claim needs both 3.2.0 and
3.3.1, and only 3.2.0 ships a prebuilt wheel for CPython 3.12 — the second one
requires a source build and a C toolchain:

```bash
pip install --no-binary jericho jericho==3.3.1
python seed_confound_demo.py --rom /path/to/zork1.z5 --out
python seed_path_demo.py     --rom /path/to/zork1.z5 --out
```

With only one version present the two `test_version_invariance` tests skip rather
than fail, so a partial reproduction leaves that claim visibly unchecked.

The field layout of the artifacts is documented in [`data/README.md`](data/README.md).

## The game file is not included

Zork I is proprietary (Infocom/Activision), and Jericho ships no game files for
the same reason. Supply your own `zork1.z5` and pass `--rom`, set `$ZORK1_ROM`,
or drop it beside the scripts (`.gitignore` keeps it out of commits).

Verification is by content hash rather than by bundling, which is the stronger
guarantee: `rom.py` refuses to run against anything whose SHA-256 is not
`0ae5ac229e79094ff368b6669356444af0f35e21d862a1baaa546989085c15fd`, the release
every committed artifact was generated against. A different Zork I release has a
different RNG tape and would silently produce numbers that disagree with the
paper. Use `--no-verify-rom` when you mean to regenerate against another release;
the actual hash is recorded in every artifact either way.

## What is here

| Path | What it is |
|---|---|
| `seed_confound_demo.py` | The seed axis: fixed actions, three seed regimes (default / `seed=0` / randomized) |
| `seed_path_demo.py` | The path axis: one frozen tape, RNG-quiet vs RNG-consuming padding before the same fight |
| `data/seed_*_demo_jericho-*.json` | The committed demo results — per-run resolved seed, score, world-state hash, ROM SHA-256, full action list |
| `data/audit_frotzenv_seeding_*.json` | The committed prevalence screen — one row per classified call site, each with a commit-pinned permalink and content hash |
| `test_seed_confound_artifact.py` | Re-derives the seed-axis claims from `data/` |
| `test_seed_path_artifact.py` | Re-derives the path-axis claims from `data/` |
| `test_rom.py` | Keeps the enforced ROM hash in lockstep with the artifacts |
| `test_audit_classifier.py` | Pins the audit script's call-site classification, the part the prevalence rate rests on |
| `test_audit_artifact.py` | Re-derives the screen's published counts from `data/`, and pins the prose that quotes them |
| `test_reading.py` | Pins the demos' printed conclusion against the committed artifacts, plus the post-fix branch no artifact can supply |
| `reading.py` | Turns measured DVs into each demo's summary, computed from the run rather than hardcoded |
| `rom.py` | ROM resolution and content verification |
| `data/README.md` | Field-by-field schema for the artifacts, and the headline reading of each |
| `data/LICENSE` | CC BY 4.0 terms for the artifact data |
| `scripts/audit_frotzenv_seeding.py` | Field-level screen: GitHub code search for `FrotzEnv`, then every `FrotzEnv(` call site in the fetched files classified by whether an explicit engine seed is passed |

The audit script needs the [`gh`](https://cli.github.com/) CLI, authenticated
(`gh auth status`); it is stdlib-only otherwise and is not covered by either
requirements file. Nothing else here needs network access.

It is a **screen, not a census**: GitHub code search ranks rather than
enumerates, caps results, and returns a different set from one run to the next.
The script's docstring sets out what its verdicts do and do not support, and
anything that lands in the paper is hand-verified. Because the search is not
reproducible, the artifact is built to be **re-verifiable instead** — every row
pins the repository's head commit, a permalink to it, and the SHA-256 of the
bytes the verdict was computed from.

The run behind the paper's figure is committed as
`data/audit_frotzenv_seeding_2026-08-13.json`: of **91 classified call sites**
across 65 repositories, **52 (57%) pass no engine seed**. That run reached
GitHub's result cap, which the artifact records as `limit_reached: true` — it is
a truncated sample and reports itself as one. Re-running will produce a different
set and different counts; that is a property of the search, not of the finding,
and it is why the numbers travel with a dated artifact instead of standing alone.

That is the only count transcribed into prose here, and `test_audit_artifact.py`
checks it against the file. The per-verdict breakdown and both denominators stay
in the artifact's `tally`, which a re-run updates on its own;
[`data/README.md`](data/README.md) documents how to read it. The classifier
behind each verdict is unit-tested in `test_audit_classifier.py`.

## Upstream

The behaviour was reported as [microsoft/jericho#84][issue] and confirmed by a
maintainer; the fix is [microsoft/jericho#88][pr], merged 2026-08-14 for the
v4.0 major release. Every release through 3.3.1 carries the silent default,
including the 3.2.0 this artifact pins.

[issue]: https://github.com/microsoft/jericho/issues/84
[pr]: https://github.com/microsoft/jericho/pull/88
